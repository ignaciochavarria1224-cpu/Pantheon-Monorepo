# Maridian Vision

Maridian is the reflective memory and self-understanding system inside Pantheon.

It is the place where journals are written, cycles are run, patterns are extracted, and the personal knowledge layer is built so Apollo can learn how you think.

Maridian is not a Dropbox folder.
Maridian is not a BlackBook feature.
Maridian is not just an Obsidian vault.

Maridian is a primary Pantheon subsystem.

## System Hierarchy

The hierarchy should be explicit:

- `Pantheon` is the parent system
- `Apollo` is the interface that will eventually use Maridian insight
- `Maridian` is the reflective memory and cycle engine
- `BlackBook` is the financial system and should remain separate

This boundary matters.

- `BlackBook` owns money
- `Maridian` owns journals, reflection, personal patterns, and memory formation
- `Apollo` should learn from both, but they should not collapse into each other

## Core Purpose

Maridian exists to help Pantheon and Apollo understand how you think over time.

It should capture:

- journal entries
- recurring thoughts
- emotional patterns
- values
- habits
- contradictions
- internal narratives
- long-term themes
- self-observations that become durable knowledge

Its job is not merely storage.
Its job is transformation.

Raw writing should become structured memory.

## What Maridian Must Do

Maridian must be responsible for:

- receiving journal entries directly
- storing reflective input in the Pantheon-owned system
- running cycles that process that writing
- generating notes, cards, summaries, questions, and index updates
- building a reliable personal knowledge layer Apollo can use later
- preserving a history of how thinking changes over time

Maridian should become the main system that teaches Apollo how you think, not by guessing, but by processing your own words over time.

## Pantheon As Maridian's Home

Maridian should live inside Pantheon completely.

That means Pantheon should be the place where you:

- write journal entries
- trigger `Run Cycle`
- view cycle status
- inspect generated notes/cards
- see question sets and index excerpts
- manage the system directly

The Maridian tab should not be a passive dashboard.
It should be the real operating surface for the subsystem.

## Obsidian's Role

Obsidian still matters, but it should not own Maridian.

Its role should be:

- direct reading surface for the canonical Maridian vault
- browsing and reading environment
- optional manual reflection environment
- human-readable representation of Maridian outputs

The source of truth should remain Pantheon-local.
Obsidian should open the canonical Maridian vault directly rather than act as a separate owner.

## BlackBook Separation

BlackBook should no longer be the place where journaling begins.

That means:

- journal ownership should move out of BlackBook
- Maridian becomes the primary journaling source
- BlackBook remains strictly financial

This separation is important because:

- financial truth needs its own clean boundary
- reflective truth needs its own clean boundary
- Apollo will become more reliable if those systems are distinct but connected

## Apollo And Maridian

Apollo should use Maridian to understand:

- how you frame decisions
- what patterns repeat
- what values show up consistently
- where you contradict yourself
- what kind of guidance actually lands

Maridian is one of the primary systems that should make Apollo feel personal rather than generic.

The end-state is not "Apollo reads journal text."
The end-state is "Apollo reads processed personal memory."

## Current Desired Interaction Model

The intended flow should be:

1. You open Pantheon and go to the Maridian tab.
2. You write a journal entry there.
3. The entry is stored in Maridian's local system.
4. You click `Run Cycle`.
5. Maridian processes the journal and updates its notes/cards/index/questions.
6. Apollo later uses those outputs to understand you better.

That is the core loop.

## Maridian Surfaces Inside Pantheon

The Maridian tab should eventually include:

- journal input
- cycle status
- run-cycle control
- latest generated cards
- latest notes
- today's or current question set
- index excerpt
- cycle history
- Obsidian access status for the canonical vault

These are not optional extras.
They are the actual control surfaces of the subsystem.

## End-State Vision

The mature Maridian system should look like this:

- fully local and Pantheon-owned
- visible and operable inside Pantheon
- directly visible in Obsidian through the canonical vault
- capable of turning raw journals into structured memory
- reliable enough that Apollo can use it as one of its main "know me" systems

In that end-state:

- BlackBook knows the money
- Maridian knows the mind
- Apollo speaks with both
- Pantheon holds the whole system together

## Final Position

Maridian should become Pantheon's reflective memory engine.

It should not live in Dropbox.
It should not stay hidden behind external folders.
It should not stay mixed into BlackBook.

It should live locally inside the repo structure, be controlled from Pantheon, mirror into Obsidian, and become one of the main systems Apollo relies on to understand how you think.
