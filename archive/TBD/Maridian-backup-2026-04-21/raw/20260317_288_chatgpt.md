## 1. Exact Derived Features for Phase 1

Everything in Variant B flows through VWAP. Grouped by dependency layer — each layer depends on the one above it.

### Layer 0 — VWAP Core (nothing works without this)

| Feature | Definition | Notes |
|---|---|---|
| `vwap` | Cumulative intraday VWAP: Σ(typical_price × volume) / Σ(volume), where typical_price = (H+L+C)/3 | Resets at session open (9:30 ET). Must use typical price, not close. |
| `vwap_dev_pct` | (close − vwap) / vwap × 100 | Signed. Positive = above VWAP. Single most important derived value in the system. |
| `vwap_dev_zscore` | Rolling z-score of `vwap_dev_pct` over N bars (start N=20) | Normalizes deviation across days with different volatility. |
| `vwap_slope` | (VWAP_now − VWAP_N_ago) / N, with N=10 | Captures whether VWAP itself is accelerating or flattening. Simple difference first, linreg later if needed. |

### Layer 1 — Volume Profile

| Feature | Definition | Notes |
|---|---|---|
| `rvol` | bar_volume / rolling_mean(volume, 20) | Relative volume. >1.5 = elevated participation. |
| `cum_volume_ratio` | Cumulative session volume / expected cumulative volume at this time-of-day | Secondary priority. Skip on first pass if historical volume curves aren't available yet. |

### Layer 2 — Raw Momentum (multi-scale)

| Feature | Definition | Notes |
|---|---|---|
| `roc_3` | (close − close_3_bars_ago) / close_3_bars_ago × 100 | Fast momentum. Noisy but responsive. |
| `roc_5` | Same, 5-bar lookback | Primary momentum signal. |
| `roc_10` | Same, 10-bar lookback | Slower trend confirmation. |
| `roc_20` | Same, 20-bar lookback | Session trend. Lags but filters chop. |
| `bar_impulse` | (close − open) / (high − low) | Normalized single-bar directional conviction. Range [−1, +1]. Default 0 if high == low. |
| `acceleration` | roc_5[i] − roc_5[i−1] | Second derivative. Positive = momentum increasing. |

### Layer 3 — Regime Classification Inputs

| Feature | Definition | Notes |
|---|---|---|
| `vwap_position` | +1 if close > vwap, −1 if close < vwap, 0 if within ±0.02% | Binary regime flag. Dead zone prevents boundary noise. |
| `vwap_cross` | True on bars where `vwap_position` flips sign from previous bar | Event detector, not continuous. |
| `bars_since_cross` | Count of bars since last `vwap_cross == True` | Regime duration. Higher = more established. Resets at cross. |
| `consec_above` | Consecutive bars with close > VWAP (0 when below) | Simpler regime duration metric. Keep both this and bars_since_cross. |
| `consec_below` | Mirror of `consec_above` for below-VWAP | Same logic, opposite side. |

### Layer 4 — Session Context

| Feature | Definition | Notes |
|---|---|---|
| `minutes_since_open` | Minutes elapsed since 9:30 ET | Continuous. Better than buckets for downstream models. |
| `session_bucket` | Categorical: `open` / `mid_am` / `lunch` / `mid_pm` / `close` | For filtering and conditional logic, not model input. |
| `session_high_vs_vwap` | (session_high_so_far − vwap) / vwap × 100 | How far the day's running high extended above VWAP. |
| `session_low_vs_vwap` | (session_low_so_far − vwap) / vwap × 100 | Mirror for low side. |

**Total: 22 derived features across 5 layers.**

**The non-obvious ordering decision:** Momentum (Step 5) is built before Volume (Step 6) even though Volume is Layer 1 and Momentum is Layer 2. Reason: momentum features are simpler, have no edge cases around zero-volume bars, and give you an immediate sanity-check surface (you can visually confirm ROC signs against price direction). Volume features require thinking about zero-volume handling and rolling window edge cases — slightly more room for subtle bugs.

### Why this prompt is structured this way:

**Dict-based, not dataclass-based.** The function takes `list[dict]` instead of your actual dataclass. This is intentional — it means you can test the math in complete isolation without importing anything from your project. Once the math is verified, Step 2 (schema) and Step 10 (integration) will wire it into your dataclass and replay loop. If you couple the feature math to your dataclass on day one, every schema change forces you to re-test the math. Keep them separate until both are individually solid.

**No numpy/pandas.** Not because they're bad — you'll likely add them later for performance. But for verification, you need to see the accumulator logic explicitly, not hidden behind a vectorized operation. Bugs in VWAP are almost always in the accumulation and reset logic, which is invisible inside `pd.Series.expanding().apply()`.

**Hand-calculated expected values in comments.** This is the part most people skip and most people regret skipping. If the expected values are wrong, the test is worthless. Showing the arithmetic in a comment means YOU can verify the expected values with a calculator before trusting the test.
